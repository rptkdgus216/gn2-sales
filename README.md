# 경남2사무소 영업활동 대시보드

화면은 **GitHub Pages**에 있고, 데이터는 **구글시트**에 있습니다. 둘 사이는 **Apps Script API**가 이어 줍니다.
이 저장소에는 **영업 데이터가 들어 있지 않습니다**. 사무소 비밀번호를 알아야만 시트에서 데이터를 받아옵니다.

```
index.html, config.js   ← GitHub Pages (화면)
apps-script/            ← 구글시트의 Apps Script에 붙여넣는 코드 (데이터 API)
```

---

## 1. Apps Script(데이터 API) 설치 — 처음 한 번

> ⚠ 시작 전에 구글시트를 **[파일 → 사본 만들기]**로 백업해 두세요.

1. 구글시트 「26년 경남2 일일결산 관리장」에서 **[확장 프로그램] → [Apps Script]**를 엽니다.
2. `Code.gs` 내용을 모두 지우고 이 저장소의 `apps-script/Code.gs`를 붙여넣습니다.
3. **[+] → 스크립트**로 `Migration`을 만들고 `apps-script/Migration.gs`를 붙여넣습니다.
4. 기존 `Index.html` 파일은 **삭제**합니다. (화면은 이제 GitHub에 있습니다)
5. **[프로젝트 설정]** (톱니바퀴)
   - 시간대: `(GMT+09:00) 서울`
   - 스크립트 속성 → 속성 추가 → 이름 `OFFICE_PASSWORD`, 값은 사무소 비밀번호
6. 편집기 위쪽 함수 선택에서 아래 순서대로 고르고 ▶ 실행합니다. (첫 실행 때 권한 승인)
   | 순서 | 함수 | 하는 일 |
   |---|---|---|
   | ① | `removeHwangDuplicate` | 9월 평가실적의 황내과 중복 행(1,428,746원) 삭제 |
   | ② | `setupSheets` | 새 탭 4개 만들기: 방문기록, 거래처(268곳), 품목, 담당자 |
   | ③ | `previewMigration` | 이관 건수 미리 확인 (실행 로그에 약 5,310건) |
   | ④ | `migrateLegacy` | 기존 개인 시트의 방문 기록을 방문기록 탭으로 옮기기 |
7. **배포**: [배포] → [배포 관리] → 기존 배포의 연필(수정) → 버전 **새 버전** → 배포
   - 실행 사용자: **나** / 액세스 권한: **모든 사용자**
   - 화면에 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
   - 확인: 그 주소를 브라우저에서 열었을 때 `{"ok":true,...}`가 보이면 정상입니다.

## 2. 화면에 API 주소 연결

이 저장소의 `config.js`를 열어 `API_URL`에 위에서 복사한 주소를 붙여넣고 저장(커밋)합니다.

```js
window.GN2_CONFIG = {
  API_URL: 'https://script.google.com/macros/s/AKfy…/exec'
};
```

## 3. GitHub Pages 켜기 — 처음 한 번

저장소 **[Settings] → [Pages]**
- Source: **Deploy from a branch**
- Branch: **main** / 폴더 **/(root)** → **Save**

1~2분 뒤 `https://<계정>.github.io/<저장소이름>/` 주소로 접속하면 됩니다. 이 주소를 직원들에게 공유하세요.

## 운영

| 상황 | 할 일 |
|---|---|
| 화면 수정 | `index.html`을 고쳐서 GitHub에 올리기 → 1~2분 뒤 반영 |
| Apps Script 코드 수정 | 붙여넣은 뒤 **[배포 관리] → 수정 → 새 버전**. 주소는 그대로라 `config.js`는 고칠 필요 없음 |
| 매월 실적 | 본사 자료를 `N월 평가실적` 탭에 붙여넣기. **내년부터는 `27년 1월 평가실적`처럼 연도를 앞에** |
| 신규 거래처 | 방문 입력 화면의 **[+ 신규 거래처]**. 코드를 모르면 비워두기 → 임시코드(TMP-…) |
| 신규처에 처방이 나옴 | 거래처 탭 → 그 신규처 → **[실적 연결]** (이름이 비슷한 곳이 ★추천으로 나옴) |
| 같은 병원인데 코드가 2개 | "미등록"으로 보이는 쪽 → **[기존 거래처에 합치기]** |
| DCM 전환 | 거래처 상세 화면에서 구분을 `DCM`으로 → 미방문 통계와 입력 목록에서 빠짐 |
| 담당 변경 / 거래처 종료 | `거래처` 탭의 담당자 수정 / 사용여부 `N` |
| 직원 입사·이동 | `담당자` 탭에 추가, 떠난 직원은 사용여부 `N`. 평가실적에 옛 이름이 나오면 "이전 담당자 이름"에 적기 |
| 비밀번호 변경 | 스크립트 속성 `OFFICE_PASSWORD` 값만 바꾸기 (재배포 불필요) |
| 잘못 입력한 방문 | `방문기록` 탭에서 그 행을 직접 수정하거나 삭제 |

## 알아둘 점
- **로그인**: 비밀번호는 Apps Script 서버에서 확인합니다. 10번 틀리면 10분 동안 잠기고, 한 번 로그인하면 6시간 유지됩니다.
- **이관 기록의 반응·품목**: 원장님 반응은 "미분류"로 들어갑니다. 3단계(AI)에서 자동으로 분류할 예정입니다. 제안 품목은 글 속 단어로 자동 인식했습니다. (예: "펙/바/실" → 펙수클루, 바로에젯, 실리스칸)
- **이관 시 방문자 구분**:
  - 고현민 시트: ~4월 박준수, 5월 계상현, 6월~ 고현민
  - 이수빈 시트: ~9/14 구원모, 9/15~ 이수빈
- **집계 기준**: 실적과 방문은 '거래처' 탭의 **현재 담당자** 기준으로 묶습니다.
- **기존 개인 시트**: 읽기만 하고 수정하지 않습니다.
